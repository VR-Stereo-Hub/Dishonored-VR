# Pre-release performance audit, the ALL-IN-ONE plan (2026-10-05): plans 1 and 2 and the stage
# profile in one unattended run. PERFORMANCE.md, "pre-release audit".
#
# Armed for ONE launch by `[Perf] AbPlanOnce=<absolute path to this file>` (the key empties itself).
# After a save is loaded there are 60 seconds to reach the spot; then stand still, hands at rest,
# for about 14 minutes. When the F10 panel opens by itself the plan is over: close it and quit.
# Pick a typical outdoor view with a light source and some smoke or fog in it: light shafts, bloom
# and translucency cost only when they are drawn. Do not pause: a menu inside a segment discards it.
#
# One segment per line: label | apply (seam words, ';' between) | restore. No apply = a baseline.
# Nothing is written to any ini while a row runs. The restore words are the dev PC's settings of
# 2026-10-04 (DLSS on with model K, HUD sharp on, anisotropy 16 with trilinear, sharpen 0.40,
# ReShade effects on) and the game's shipped engine values (ShadowTexelsPerPixel 1.27324,
# MaxShadowResolution 800, ScreenPercentage 100).
#
# Part A measures our own costs with nothing else running. The row "stage profile ON" then switches
# the engine's stage events on and LEAVES them on, so every later baseline and row carries a
# `perf/stages:` table (CPU, GPU and draws per engine stage) and the same profiling overhead.
# Compare a row with the baselines either side of it, not with the plan's overall noise floor.
# The two rows that change the render size are last, so a fault there costs nothing before it.
